# 6. Нефункциональные требования

## 6.1 Приватность и безопасность

Дневник — самая личная категория данных, какая бывает в приложениях. Требования ниже не
«для галочки»: если пользователь не доверяет продукту, он не станет вести в нём дневник.

| ID | Приор. | Требование |
| --- | --- | --- |
| NFR-01 | M | Все данные доступны только владельцу. Любой запрос к записи, человеку, вишлисту проверяет владельца, а не только наличие авторизации |
| NFR-02 | M | Передача данных только по HTTPS; файлы вложений отдаются по подписанным ссылкам с ограниченным сроком действия, а не по угадываемым путям |
| NFR-03 | M | Пароли хранятся в виде хешей современным алгоритмом; вход по e-mail и паролю с ограничением частоты попыток |
| NFR-04 | M | Блокировка приложения кодом/биометрией при возврате из фона (отдельная настройка, по умолчанию выключена) |
| NFR-05 | M | Публичная ссылка на вишлист (WL-11) отдаёт только выбранные позиции и не раскрывает ничего другого: ни людей, ни записи, ни другие вишлисты |
| NFR-06 | M | Публичные страницы закрыты от индексации (`noindex`, `robots.txt`), ссылку можно отозвать, после отзыва старый адрес перестаёт работать немедленно |
| NFR-07 | M | Приложение не отправляет данные третьим сторонам. Внешние запросы возможны только по явному действию пользователя (например, WL-10 «заполнить по ссылке»), с предупреждением о том, что сайт увидит обращение |
| NFR-08 | M | Загружаемые файлы (изображения, шрифты) проверяются по содержимому, обрабатываются в изоляции и никогда не исполняются; из изображений удаляются метаданные, включая координаты |
| NFR-09 | M | Пользовательский HTML/Markdown санитизируется при отображении и экспорте (защита от XSS через вставленный текст) |
| NFR-10 | S | Полное удаление аккаунта со всеми данными и файлами, по запросу пользователя, с подтверждением |
| NFR-11 | C | Сквозное шифрование тела записей ключом, производным от пароля пользователя. Требует решения о восстановлении доступа при утере пароля — см. Q7 |
| NFR-12 | M | Встраивание содержимого сторонних сервисов (музыкальный виджет, см. [15-music.md](15-music.md)) допустимо только после явного согласия пользователя, с объяснением, что сервис увидит обращение. Согласие отзывается в настройках, до согласия сторонний код не загружается |

## 6.7 Квоты и сроки хранения

Числа собраны в одном месте, потому что они разбросаны по разным разделам и должны быть
согласованы между собой. Значения — предложение (см. Q16), но структура ограничений
обязательна: пользователь должен заранее знать пределы, а не узнавать о них при отказе.

| Ограничение | Значение | Поведение при достижении |
| --- | --- | --- |
| Один файл изображения | 15 МБ | Загрузка отклоняется с предложением уменьшить |
| Один файл шрифта | 5 МБ | Отклоняется (ED-62) |
| Все шрифты пользователя | 50 МБ | Загрузка новых блокируется, существующие работают (ED-62) |
| Всё хранилище пользователя | по тарифу, по умолчанию 2 ГБ | Предупреждение при 80%, запрет загрузки при 100%; данные не удаляются (Q16) |
| Длина записи | 200 тыс. знаков | Предупреждение при 150 тыс.: дальше редактор может замедляться |
| Позиций в вишлисте | 500 на список | Предупреждение; экспорт PDF предлагает разбить на части |
| Треков в диске | 100 | Предупреждение при добавлении |
| Людей в картотеке | без жёсткого предела | Список виртуализирован (NFR-42) |

| Срок хранения | Значение | Примечание |
| --- | --- | --- |
| Корзина (записи, люди, желания) | 30 дней | Уведомление за 3 дня до окончательного удаления (NAV-44) |
| История версий записи | последние 50 версий + все конфликтные | Прореживание: по одной за час за сутки, далее по одной в день (5.5) |
| Журнал напоминаний | 12 месяцев | Нужен, чтобы разбирать жалобы «уведомление не пришло» (PPL-65) |
| Технические логи | 30 дней | Без личного содержимого (NFR-73) |
| Ссылки на готовые файлы экспорта | 24 часа | Подписанные ссылки с истечением (12.9) |
| Данные удалённого аккаунта | удаляются в течение 7 дней | Включая файлы и резервные копии (NFR-10) |

| ID | Приор. | Требование |
| --- | --- | --- |
| NFR-80 | M | Все лимиты и сроки заданы конфигурацией в одном месте, а не «зашиты» по коду: их изменение не должно требовать правок в десяти файлах |
| NFR-81 | M | Занятое место и остаток квоты видны в настройках с разбивкой по типам файлов (SET-05) |
| NFR-82 | M | Приближение к лимиту сообщается заранее (80%), а не в момент отказа |
| NFR-83 | M | Достижение лимита никогда не приводит к потере уже введённых данных: блокируется только добавление нового |

## 6.8 Надёжность и наблюдаемость

| ID | Приор. | Требование |
| --- | --- | --- |
| NFR-70 | M | Потеря введённого текста недопустима: черновик сохраняется локально до подтверждения записи на сервере |
| NFR-71 | M | Ошибка сети при сохранении сообщается явно, с кнопкой «Повторить», без потери введённых данных |
| NFR-72 | M | Фоновые задачи напоминаний идемпотентны и переживают перезапуск сервиса без дублей и пропусков |
| NFR-73 | S | Технические логи ошибок не содержат тел записей, заметок и других личных текстов |
| NFR-74 | S | Метрики доставки уведомлений (отправлено / не доставлено), чтобы дефекты напоминаний были заметны до жалоб |
