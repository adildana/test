# 8. Открытые вопросы

Вопросы, которые нельзя решить в документе — нужен выбор заказчика. Для каждого указано,
что блокируется решением, и предлагаемый вариант по умолчанию.

| № | Вопрос | Что блокирует | Предложение по умолчанию |
| --- | --- | --- | --- |
| **Q1** | Как хранить документ: Markdown с инлайновым HTML, Markdown + слой аннотаций или структура с экспортом в Markdown? (см. 2.1) | Этап 1 целиком: редактор, поиск, экспорт, синхронизация | Структура документа как основной формат, Markdown — импорт/экспорт |
| **Q2** | Платформа: веб-приложение, мобильное приложение или настольное? | Выбор стека, работа офлайн, способ доставки уведомлений | Веб-приложение с поддержкой установки на телефон (PWA) — уведомления и офлайн доступны, разработка одна |
| **Q3** | Данные хранятся на сервере или только на устройстве? | Приватность, синхронизация, восстановление после потери устройства, стоимость эксплуатации | Сервер с полным экспортом данных по запросу; локальный режим — как отдельная возможность позже |
| **Q4** | Один пользователь или многопользовательский сервис? | Аккаунты, изоляция данных, публичные ссылки на вишлист | Многопользовательский с самого начала: добавить изоляцию потом дороже, чем сразу |
| **Q5** | Использовать внешний каталог книг для автозаполнения (ED-53)? Если да — какой источник? | Автозаполнение автора и обложки по названию/ISBN | Отложить; в MVP заполнение вручную |
| **Q6** | Разрешить приложению обращаться к сайту по ссылке, чтобы заполнить позицию вишлиста (WL-10)? Обращение раскрывает магазину факт интереса | Функция «добавить по ссылке» | Разрешить только по явному нажатию, с предупреждением; по умолчанию выключено |
| **Q7** | Нужно ли сквозное шифрование записей (NFR-11)? При нём восстановление пароля невозможно без потери данных | Архитектура хранения, поиск по тексту (по зашифрованному искать нельзя обычными средствами) | Не в MVP; вместо этого блокировка приложения кодом и шифрование хранилища |
| **Q8** | Шкала оценки книг: 5 или 10 звёзд, нужны ли половинки и оценки по критериям? | Шаблон книги и статистика (нельзя менять шкалу задним числом без пересчёта) | 5 звёзд с половинками, критерии — опционально, включаются в настройках шаблона |
| **Q9** | Как обрабатывать смену шкалы оценки, если записи уже созданы? | Целостность статистики | Шкала фиксируется в шаблоне; при изменении предлагается пересчёт с явным подтверждением |
| **Q10** | Нужны ли несколько вишлистов или достаточно одного (3.1)? | Навигация и модель данных вишлиста | Модель на несколько списков, интерфейс — с одним списком по умолчанию |
| **Q11** | Валюта в вишлисте: одна основная или произвольная у каждой позиции? Нужен ли пересчёт по курсу (WL-09)? | Итоговая сумма и экспорт | Валюта у каждой позиции, основная — в настройках; курс сохраняется на момент ввода |
| **Q12** | Каналы уведомлений в MVP: только внутри приложения, push или e-mail (PPL-61)? | Инфраструктура доставки, необходимость почтового сервиса | В MVP — внутри приложения и push; e-mail позже |
| **Q13** | Максимальная частота напоминаний в режиме «ежедневно» (PPL-54): нужно ли ограничение, чтобы пользователь не завалил себя уведомлениями? | Логика планировщика | Ограничить 30 днями до события и предупреждать при выборе больше 14 дней |
| **Q14** | Нужен ли учёт часового пояса человека для напоминаний или достаточно пояса пользователя (PPL-46)? | Планировщик напоминаний | Планировать по поясу пользователя, пояс человека — только справочно |
| **Q15** | Что показывать в карточке человека первым: анкету или ленту комментариев? | Компоновка главного экрана карточки | Анкета сверху, лента ниже; на телефоне — переключаемые вкладки |
| **Q16** | Нужно ли ограничение размера хранилища на пользователя (фото, шрифты)? | Стоимость эксплуатации, поведение при переполнении | Квота с предупреждением при 80% и запретом загрузки при 100%, без удаления данных |
| **Q17** | Нужны ли предустановленные наборы стилей («классический», «рукописный», «минимальный») или пользователь настраивает с нуля? | Объём работ по этапу 4 | Три предустановленных набора + возможность создать свой |
| **Q18** | Как показывать диск, не нарушая правила встраивания YouTube? Правила требуют официальный видимый плеер и запрещают его перекрывать и отделять звук от видео (16.6). Точную редакцию правил нужно сверить перед реализацией | Внешний вид всего музыкального модуля; при неверном решении — риск блокировки встраивания | Вариант A + B из 16.6: до нажатия статичный винил, после — вращающееся кольцо вокруг видимого плеера |
| **Q19** | Ограничиться YouTube или сразу поддержать другие источники (Spotify, Apple Music, Яндекс Музыка, свои аудиофайлы)? | Архитектура источников в музыкальном модуле | В первой версии только YouTube, но модель данных с полем `source` под расширение (MUS-44) |
| **Q20** | Хватит ли публичного oEmbed для метаданных или нужен ключ YouTube Data API (длительность, разбор плейлистов)? | Добавление плейлистов целиком, показ длительности треков | Начать с oEmbed без ключа; плейлисты и длительность — после решения о ключе |
| **Q21** | Нужно ли обещать фоновое воспроизведение при свёрнутом браузере? Платформы этого не гарантируют | Ожидания пользователя и выбор платформы (Q2) | Не обещать; в настройках дать честное пояснение (MUS-61) |
| **Q22** | Нужна ли история прослушиваний и статистика по музыке? | Ещё один журнал личных данных | Не в первой версии |
