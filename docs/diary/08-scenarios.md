# 9. Сценарии использования и критерии успеха

Требования в разделах 2–4 отвечают на вопрос «что должно быть». Этот раздел отвечает на
вопрос «как этим пользуются» — и служит проверкой: если сквозной сценарий не проходится без
запинок, набор требований неполный, даже когда каждое требование по отдельности выполнено.

---

## 9.1 Роли

| Роль | Описание | Права |
| --- | --- | --- |
| **Владелец** | Единственный полноценный пользователь: ведёт дневник, вишлисты, картотеку людей | Полный доступ ко своим данным |
| **Гость по ссылке** | Тот, кому владелец дал публичную ссылку на вишлист (WL-11) | Только чтение выбранных позиций одного вишлиста, без регистрации |
| **Администратор системы** | Обслуживает сервис | Управление аккаунтами и квотами, **без доступа к содержимому записей** (NFR-73) |

## 9.3 Сквозные сценарии

### SC-01. Первый запуск

1. Регистрация, выбор языка и часового пояса.
2. Онбординг из трёх шагов (ONB-01…ONB-05): что такое записи, вишлист, люди.
3. Предложение сразу создать первую запись из шаблона «День» либо пропустить.
4. Автоматически создаются: категории людей по умолчанию, вишлист «Мои желания»,
   набор стилей по умолчанию.

**Критерий:** до первой сохранённой записи — не больше двух минут и не больше одного
обязательного шага настройки.

### SC-02. Вечерняя запись в дневник

1. Главный экран → «Новая запись» (или горячая клавиша `N`).
2. Дата подставлена сегодняшняя, курсор в теле записи.
3. Пользователь пишет текст, часть выделяет полужирным кнопкой панели, добавляет чек-лист.
4. Уходит, не нажимая «Сохранить»: запись сохранена автосохранением (ED-02).

**Критерий:** ни одного обязательного поля, кроме тела; ни одного диалога по пути.

### SC-03. Дочитал книгу

1. «Новая запись» → шаблон «Оценка прочитанной книги».
2. Название и автор — с автодополнением по ранее введённым (2.3).
3. Статус «Прочитана» → дата окончания подставляется сегодняшней.
4. Оценка звёздами, две цитаты, отзыв в теле записи.
5. Запись появляется и в дневнике по дате, и в разделе «Книги», и в статистике года.

**Критерий:** запись о книге не требует ручного дублирования данных в отдельный «раздел книг» —
раздел строится из записей автоматически (ED-50).

### SC-04. Подготовка вишлиста ко дню рождения

1. Раздел «Вишлист» → «+» несколько раз, вводятся только названия желаний.
2. Позже к части позиций добавляются фото, цены и ссылки (US-21).
3. Порядок меняется перетаскиванием: важное — наверх (WL-04).
4. «Скачать PDF» → режим выбора → снимаются флажки с трёх личных позиций (WL-21).
5. Настройки экспорта: макет «карточки», включить фото и ссылки, выключить цены (WL-22, WL-23).
6. Предпросмотр (WL-28) → скачивание файла `Вишлист — На день рождения — 2026-09-14.pdf`.

**Критерий:** PDF читается на бумаге и на телефоне, кириллица не превращается в квадратики,
позиции не разрываются между страницами (3.4).

### SC-05. Новый знакомый после встречи

1. «Люди» → «+» → вводится имя, выбирается категория «Коллеги» → сохранено.
2. Вставляется ссылка на телеграм в виде `@ivanov` → поле превращается в кнопку-иконку (PPL-25).
3. Раскрывается блок «Подробнее», добавляется фамилия и прозвище (PPL-10).
4. В ленту комментариев добавляется запись: «познакомились на конференции, занимается
   дизайном» (PPL-91).

**Критерий:** от нажатия «+» до сохранённой карточки — одно обязательное поле (PPL-102).

### SC-06. Настройка напоминания о дне рождения

1. В карточке человека вводится день рождения (год неизвестен — вводится только день и месяц, PPL-42).
2. «Уведомлять» включено по умолчанию (PPL-50) → напоминание в день события уже работает,
   больше ничего настраивать не нужно.
3. Пользователь дополнительно ставит флажки «за неделю» и «за месяц» (PPL-52).
4. Под настройками сразу видно расписание: «Напомню 14 августа, 7 сентября и 14 сентября
   в 10:00» (PPL-57).

**Критерий:** базовый случай работает без настройки; расширенный не требует понимания
внутренней логики, потому что расписание показано словами.

### SC-07. Наступил день напоминания

1. За неделю до даты в 10:00 приходит уведомление: «Через 7 дней день рождения у Марии».
2. В уведомлении — подсказки: любимые цвета, «любит/не любит», две позиции из вишлиста,
   помеченные «для Марии» (PPL-59).
3. Нажатие открывает карточку человека; кнопка «отложить на час» и «отметить как
   поздравлено» (PPL-60).
4. Если устройство было офлайн, уведомление показывается при следующем открытии, но не
   дублируется (PPL-62, PPL-63).

### SC-08. Настройка своего оформления

1. Настройки → «Шрифты» → загрузка файлов семейства (обычный, полужирный, курсив) (ED-61).
2. Приложение проверяет файлы, спрашивает подтверждение прав на использование (ED-66),
  предупреждает, что в шрифте нет кириллицы, если её нет (ED-68).
3. Настройки → «Стили» → в стиле «Заголовок 1» выбирается загруженный шрифт, кегль и цвет (ED-81).
4. Все существующие записи с этим набором стилей меняют оформление сразу (ED-82).

### SC-09. Поиск старой записи

1. Поиск (`Ctrl/Cmd+K`) → «море» → результаты сгруппированы: записи, книги, люди, желания (SRCH-02).
2. Фильтры: только записи, 2024 год (SRCH-03).
3. Найденное открывается с подсветкой совпадений (SRCH-05).

### SC-10. Диск под запись

1. В открытой записи пользователь включает музыкальный виджет (MUS-01).
2. Первое включение: приложение объясняет, что музыку проигрывает плеер YouTube, и просит
   согласие (MUS-50). Пользователь соглашается — согласие запрашивается один раз.
3. Вставляется ссылка `https://youtu.be/…?t=95`; название, исполнитель и обложка
   подтягиваются автоматически, начало ставится на 1:35 (MUS-03, MUS-12).
4. Ещё четыре ссылки добавляются через «+», порядок меняется перетаскиванием (MUS-04).
5. Нажатие «Играть»: только теперь загружается плеер, диск начинает вращаться (MUS-06, MUS-40).
6. Пользователь уходит в раздел «Люди» — музыка продолжает играть в мини-плеере (MUS-08).
7. Через месяц запись открывается снова: диск на месте, один трек помечен как недоступный,
   его ссылка сохранена (MUS-33, MUS-34).

**Критерий:** ни одного запроса к внешнему сервису до нажатия «Играть»; запись открывается
так же быстро, как без диска (MUS-40, NFR-40).

### SC-11. Музыка человека

1. В карточке человека заполняется раздел «Его музыка» — три песни (MUS-21).
2. За неделю до дня рождения приходит напоминание, в подсказках — любимые цвета, «любит /
   не любит» и эти песни (PPL-59, MUS-25).
3. Из уведомления открывается карточка, диск запускается одним нажатием.

### SC-12. Переход на новое устройство

1. Настройки → «Данные» → «Экспорт всех данных» → архив (NFR-20).
2. Вход на новом устройстве → всё на месте благодаря синхронизации (NFR-31), а архив
   остаётся как личная резервная копия, не зависящая от сервиса.

## 9.5 Критерии успеха

Продукт личный, поэтому измерять его нужно удобством, а не вовлечённостью. Метрики
собираются локально и обезличенно; телеметрия по содержимому записей не собирается никогда
(NFR-73).

| Критерий | Целевое значение | Почему именно так |
| --- | --- | --- |
| Время до первой сохранённой записи у нового пользователя | < 2 мин | Если дневник не открылся сразу, к нему не возвращаются |
| Время создания обычной записи | < 30 с на 500 знаков без задержек ввода | Дневник конкурирует с заметками в телефоне |
| Время заполнения позиции вишлиста (только название) | < 10 с | Иначе «+» не используют повторно |
| Время заполнения карточки человека (минимум) | < 20 с | Карточку заводят в момент знакомства, на ходу |
| Доля напоминаний, доставленных в запланированное окно ±5 мин | > 99% | Пропущенный день рождения = потеря доверия к продукту целиком |
| Доля дублирующихся напоминаний | 0 | Дубли раздражают сильнее, чем отсутствие функции |
| Потери пользовательского текста | 0 случаев | Единственный полностью недопустимый дефект |
| Успешность экспорта PDF на 100 позиций | 100%, < 10 с | Сценарий SC-04 — главный «выход наружу» |
| Возврат к дневнику через неделю после первой записи | > 40% | Признак того, что шаблоны и напоминания действительно помогают |
