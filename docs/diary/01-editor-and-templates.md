# 2. Редактор, шаблоны, шрифты и стили

Исходные формулировки заказчика:

> Шаблоны для дневника: оценка прочитанных книг.
> Маркдаун шаблоны для редакции текста как в гугл доке и в майкрософт ворде. Будет верхняя
> выдвижная панель, где можно выбрать кнопочки и т. д. для редактирования стиля и оформления текста.
> Можно загружать свои шрифты и настраивать стили текстов и редактировать их.

Ниже это разложено на четыре части: редактор, панель форматирования, шаблоны, шрифты и стили.

## 2.1 Редактор записи

### Формат хранения

Тело записи хранится в **Markdown** — это прямое требование заказчика и одновременно
гарантия того, что записи останутся читаемыми и переносимыми даже без приложения.

Важное проектное решение: пользователь хочет «как в Google Docs», то есть **WYSIWYG** —
он не должен видеть символы `**` и `#`. Значит:

- пользователь редактирует визуальное представление;
- при сохранении оно сериализуется в Markdown;
- при открытии — разбирается обратно.

Отсюда следует ограничение, которое нужно принять сознательно: **чистый Markdown не умеет
выражать цвет текста, выравнивание, произвольный шрифт и размер.** Варианты решения
(окончательный выбор — в [07-open-questions.md](07-open-questions.md), вопрос Q1):

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| Markdown + инлайновый HTML (`<span style="…">`) | Файл остаётся `.md`, открывается где угодно | Оформление теряется при открытии в другом редакторе; нужно санитизировать HTML |
| Markdown + отдельный слой оформления (аннотации со смещениями) | Текст остаётся чистым, оформление не мешает поиску и экспорту | Смещения нужно пересчитывать при правках, риск рассинхронизации |
| Хранить документ структурой (JSON) и экспортировать в Markdown | Максимально надёжно и просто в реализации редактора | Markdown становится форматом экспорта, а не хранения |

**Рекомендация:** хранить структуру документа (третий вариант) и держать Markdown как
формат импорта/экспорта. Пользовательское требование «маркдаун-шаблоны» при этом
выполняется: шаблоны пишутся и хранятся в Markdown, а форматирование не ломается.

### Поддерживаемые блоки и инлайн-элементы

- **Блоки:** абзац, заголовки H1–H3, маркированный список, нумерованный список, чек-лист,
  цитата, блок кода, таблица, изображение, разделитель, свёрнутый блок (спойлер).
- **Инлайн:** полужирный, курсив, подчёркнутый, зачёркнутый, моноширинный, ссылка,
  цвет текста, цвет фона (маркер), верхний/нижний индекс, упоминание человека (`@`).

## 2.2 Верхняя выдвижная панель форматирования

Заказчик описал её как «верхняя выдвижная панель, где можно выбрать кнопочки для
редактирования стиля и оформления текста». Ниже — детализация поведения.

### Поведение панели

| ID | Приор. | Требование |
| --- | --- | --- |
| ED-20 | M | Панель закреплена у верхней границы области редактирования и остаётся видимой при прокрутке текста |
| ED-21 | M | Панель имеет два состояния: **свёрнутое** (одна строка с самыми частыми кнопками) и **развёрнутое** (все группы кнопок). Переключение — кнопкой-шевроном и по `Ctrl/Cmd+Shift+F` |
| ED-22 | M | Состояние панели (свёрнута/развёрнута) запоминается между сессиями |
| ED-23 | M | Кнопки отражают состояние курсора: если курсор внутри полужирного текста, кнопка «Ж» показана активной |
| ED-24 | M | Кнопки, недопустимые в текущем контексте, показаны неактивными, а не скрыты (например, «объединить ячейки» вне таблицы) |
| ED-25 | S | На узких экранах (< 768 px) панель превращается в горизонтально прокручиваемую ленту, а редкие действия уходят в меню «⋯» |
| ED-26 | S | Выделение текста мышью дополнительно вызывает компактную плавающую панель рядом с выделением (как в Google Docs) |
| ED-27 | S | Состав и порядок групп кнопок настраиваются пользователем; есть кнопка «сбросить по умолчанию» |
| ED-28 | M | У каждой кнопки есть подсказка при наведении с названием действия и горячей клавишей |
| ED-29 | M | Вся панель доступна с клавиатуры: вход в панель по `F10`, перемещение стрелками, кнопки озвучиваются экранным диктором |

### Состав панели

Свёрнутое состояние (одна строка):

```
[Стиль ▾] [Шрифт ▾] [Размер ▾] │ Ж К Ч З │ A▾ ✎▾ │ • ≡ ☑ │ 🔗 │ ⌄
```

Развёрнутое состояние — группы:

1. **История:** отменить, повторить, очистить форматирование.
2. **Стили:** выпадающий список текстовых стилей (Обычный текст, Заголовок 1–3, Цитата,
   Подпись, Код) + пункт «Изменить стили…».
3. **Шрифт:** семейство (включая загруженные пользователем), кегль, интерлиньяж,
   межбуквенное расстояние.
4. **Начертание:** полужирный, курсив, подчёркнутый, зачёркнутый, моноширинный,
   верхний/нижний индекс.
5. **Цвет:** цвет текста, цвет выделения (маркер) — палитра + ввод HEX + недавние цвета.
6. **Абзац:** выравнивание (лево/центр/право/по ширине), отступы, интервалы до/после.
7. **Списки:** маркированный, нумерованный, чек-лист, увеличить/уменьшить уровень.
8. **Вставка:** ссылка, изображение, таблица, разделитель, цитата, блок кода, эмодзи,
   упоминание человека, вставка блока из шаблона.

## 2.3 Шаблоны записей

### Устройство шаблона

Шаблон = **набор структурированных полей** + **тело в Markdown** + метаданные
(название, иконка, категория). Структурированные поля нужны, чтобы по записям можно было
считать статистику (например, средняя оценка книг за год), чего нельзя сделать по свободному тексту.

Поддерживаемые типы полей: текст (строка), длинный текст, число, дата, диапазон дат,
оценка (звёзды), выбор из списка, мультивыбор, флажок, ссылка, изображение, цвет,
ссылка на человека, теги.

| ED-40 | M | Библиотека шаблонов: список с поиском, превью и кнопкой «Создать запись» |
| ED-41 | M | Набор системных шаблонов из коробки (см. ниже) |
| ED-42 | M | Создание своего шаблона: добавление полей, их порядок, обязательность, значения по умолчанию |
| ED-43 | M | Сохранение существующей записи как шаблона («Сохранить как шаблон») |

| ED-45 | S | Дублирование, архивирование и удаление шаблона; при удалении записи сохраняются, поля становятся обычным текстом |

Заказчик прямо назвал один шаблон — «Оценка прочитанных книг». Остальные предлагаются как
разумный стартовый набор (и как демонстрация возможностей движка шаблонов): день,
благодарность, тренировка, просмотренный фильм, путешествие, встреча, идея, цели месяца,
итоги года.

**Безопасность:** файлы шрифтов раздаются как статические файлы с `Content-Type: font/*`,
`Content-Disposition: attachment` при прямом обращении и без выполнения какого-либо
содержимого. Шрифт — бинарный файл, который может содержать некорректные таблицы, поэтому
парсер должен работать в изоляции и отклонять файл при любой ошибке разбора,
а не пытаться его починить.

**Ограничение, о котором нужно предупредить в интерфейсе:** оформление, заданное стилями и
своими шрифтами, полностью сохраняется внутри приложения и в экспорте в PDF/DOCX/HTML.
При экспорте в чистый Markdown сохраняется только структура (заголовки, списки, выделение),
а шрифты, цвета и выравнивание теряются — это свойство формата, а не дефект.
