# 19. Переносимость данных: экспорт и импорт

Раздел детализирует NFR-20…NFR-24. Причина отдельного раздела: обещание «данные ваши»
проверяется не текстом лицензии, а тем, можно ли забрать записи и прочитать их без
приложения. Поэтому структура архива и форматы фиксируются на уровне спецификации, а не
оставляются на усмотрение реализации.

---

## 19.1 Принципы

1. **Экспорт полный и бесплатный.** Ни одна часть данных не остаётся «внутри» (NFR-21).
2. **Архив читаем человеком.** Записи — Markdown, вложения — обычные файлы в понятных папках.
   Открыв архив в файловом менеджере, пользователь понимает, что где лежит.
3. **Архив читаем машиной.** Рядом с Markdown лежит JSON со структурированными данными: то,
   что нельзя выразить текстом (правила напоминаний, данные виджетов, порядок позиций).
4. **Импорт обратим.** Экспорт и импорт — пара: архив, выгруженный сегодня, загружается
   обратно без потерь и без дублей.

## 19.2 Форматы

| Формат | Что даёт | Требование |
| --- | --- | --- |
| **Полный архив** (`.zip`) | Всё: записи, вложения, шрифты, структурированные данные | PORT-01 |
| **Дерево Markdown** | Только записи с вложениями, для Obsidian-подобных хранилищ | PORT-10 |
| **PDF** | Отдельная запись или вишлист (ED-11, WL-20) | 3.4 |
| **ICS** | Важные даты для календаря (PPL-47) | PPL-47 |
| **CSV** | Вишлист и список книг для таблиц | WL-30 |

│   ├── 2026/
│   │   ├── 2026-08-28-vecher-doma.md
│   │   ├── 2026-08-28-vecher-doma.json

│   ├── mariya-ivanova.md          # человекочитаемая карточка

│   ├── na-den-rozhdeniya.md
│   └── na-den-rozhdeniya.json
├── music/

├── styles/

| ID | Приор. | Требование |
| --- | --- | --- |
| PORT-01 | M | Полный архив содержит все данные пользователя: записи, поля шаблонов, вложения, людей с датами и правилами напоминаний, вишлисты, диски, шаблоны, стили, шрифты, теги, настройки |
| PORT-02 | M | У каждой записи два файла: `.md` (текст, читаемый без приложения) и `.json` (структурированные данные — поля шаблона, виджеты, ссылки на вложения) |
| PORT-03 | M | Имена файлов транслитерируются, приводятся к нижнему регистру и не содержат символов, запрещённых в файловых системах; при совпадении имён добавляется суффикс |
| PORT-04 | M | Вложения лежат файлами, а не в base64 внутри JSON: архив должен быть пригоден для просмотра фотографий обычной программой |
| PORT-05 | M | Шрифты выгружаются как файлы вместе с датой подтверждения лицензии (ED-66) |
| PORT-06 | M | Экспорт — фоновая задача с прогрессом; ссылка на архив подписанная и с ограниченным сроком (12.9) |
| PORT-07 | M | Архив не содержит служебных идентификаторов вида «внутренний номер строки БД» без необходимости: идентификаторы стабильны и нужны только для восстановления связей |

## 19.4 manifest.json

```json
{
  "format": "diary-archive",
  "format_version": 1,
  "app_version": "1.4.2",
  "exported_at": "2026-08-28T18:05:00Z",
  "locale": "ru",
  "timezone": "Asia/Almaty",
  "counts": {
    "entries": 412, "people": 37, "wishlists": 3, "wishlist_items": 61,
    "templates": 11, "discs": 24, "attachments": 508, "fonts": 2
  },
  "checksums": { "algorithm": "sha256", "files": { "entries/2026/2026-08-28-vecher-doma.md": "9f2c…" } },
  "notes": ["Оформление, заданное стилями, сохранено в styles/style-sets.json; в .md-файлах остались только структура и текст"]
}
```

| ID | Приор. | Требование |
| --- | --- | --- |
| PORT-08 | M | `format_version` увеличивается при несовместимых изменениях; импорт умеет читать все предыдущие версии формата |
| PORT-09 | M | Контрольные суммы позволяют проверить целостность архива; при импорте несовпадение сообщается, но не блокирует загрузку остальных файлов |

## 19.5 Представление записи

Markdown-файл с заголовком метаданных (frontmatter) — это делает архив совместимым с
Obsidian-подобными хранилищами без потери информации:

```markdown
---
id: 8f21c0d4
date: 2026-08-27
title: Дюна
template: kniga
tags: [фантастика, классика]
people: [pyotr-sokolov]
fields:
  author: Фрэнк Герберт
  status: finished
  rating: 4
  started_at: 2026-08-12
  finished_at: 2026-08-27
widgets:
  - type: mood
    data: { value: 4 }
  - type: music_disc
    data: { disc_id: 4c19a2 }
---

# Впечатление

Дочитал за две недели. Сильнее всего запомнилась линия…

> Страх — убийца разума. — с. 24

![Обложка](../attachments/entries/2026/08/dune-cover.webp)

## Музыка этого дня

- Ludovico Einaudi — Nuvole Bianche — https://youtu.be/kfLuuLLLtiY
```

| ID | Приор. | Требование |
| --- | --- | --- |
| PORT-10 | M | Режим «дерево Markdown»: только `.md`-файлы и вложения, с относительными ссылками на изображения — так, чтобы папку можно было открыть в любом редакторе Markdown |
| PORT-11 | M | Виджеты в Markdown представлены текстом (WID-06): настроение — значением, чек-лист — списком с отметками, диск — списком ссылок, галерея — изображениями |
| PORT-12 | M | Ссылки между объектами сохраняются: упоминание человека в записи превращается в ссылку на файл его карточки |

## 19.6 Что теряется и почему

Честный список — он же текст, который показывается пользователю перед экспортом:

| Что | Где сохраняется | Что теряется в чистом Markdown |
| --- | --- | --- |
| Оформление стилями и своими шрифтами | `styles/`, PDF, HTML | Цвет, кегль, выравнивание, шрифт (2.5) |
| Данные виджетов | `.json` записи | Интерактивность: чек-лист становится статичным списком |
| Правила напоминаний | `people/*.json` | Автоматическая отправка (уведомления работают только в приложении) |
| Музыка | `music/discs.json`, ссылки в `.md` | Воспроизведение: аудио не хранится и не выгружается (MUS-43) |
| История версий записей | не выгружается по умолчанию | Промежуточные версии; текущая версия сохранена полностью |
| Публичные ссылки на вишлисты | `wishlists/*.json` (факт наличия) | Сами адреса — они отзываются при экспорте не автоматически, но и не переносятся |

| ID | Приор. | Требование |
| --- | --- | --- |
| PORT-13 | M | Перед экспортом показывается краткий список того, что не переносится в выбранный формат — без мелкого шрифта и оговорок |
| PORT-14 | S | Историю версий можно включить в архив флажком |

## 19.7 Импорт

| ID | Приор. | Требование |
| --- | --- | --- |
| PORT-20 | S | Импорт полного архива восстанавливает данные вместе со связями: люди, даты, правила напоминаний, вишлисты, диски, шаблоны, стили, шрифты |
| PORT-21 | S | Импорт идемпотентен: повторная загрузка того же архива не создаёт дублей (сверка по `id` объектов) |
| PORT-22 | S | Режим импорта выбирается явно: **добавить** к существующим данным или **заменить** всё. По умолчанию — добавить |
| PORT-23 | S | Конфликты (объект с тем же `id`, но другим содержимым) решаются по правилам синхронизации: сохраняются обе версии, пользователь выбирает (NFR-32) |
| PORT-24 | S | Частичный импорт: можно загрузить только записи, только людей или только вишлисты |
| PORT-25 | S | Перед импортом показывается отчёт-предпросмотр: сколько объектов будет добавлено, изменено, пропущено |
| PORT-26 | S | Импорт папки Markdown без метаданных: дата берётся из имени файла или из первой строки, заголовок — из первого заголовка; всё, что не распознано, попадает в тело записи, ничего не отбрасывается молча |
| PORT-27 | S | Импорт людей из vCard с дедупликацией по имени и дню рождения, с предпросмотром (PPL-105) |
| PORT-28 | M | Файлы архива при импорте проверяются как любые загружаемые файлы: тип по содержимому, размеры, санитизация HTML (NFR-08, NFR-09). Архив из чужих рук не должен становиться способом атаки |
| PORT-29 | S | Прерванный импорт не оставляет половину данных: операция выполняется транзакционно или откатывается |

## 19.8 Резервные копии

| ID | Приор. | Требование |
| --- | --- | --- |
| PORT-30 | S | Автоматическое резервное копирование по расписанию (ежедневно / еженедельно) в выбранное пользователем место (NFR-23) |
| PORT-31 | S | Хранится несколько последних копий; старые удаляются по правилу, известному пользователю |
| PORT-32 | S | В настройках видно, когда была последняя успешная копия; неудача показывается явно, а не только в логах |
| PORT-33 | C | Проверка восстановления: копию можно открыть в режиме просмотра, не заменяя текущие данные |

## 19.9 Проверка

Тест-кейсы — в [13-acceptance-criteria.md](13-acceptance-criteria.md), раздел 14.6,
группа TC-PORT. Ключевой из них: **выгрузить архив, удалить аккаунт, восстановить из архива
и сравнить** — это единственная проверка, которая доказывает, что обещание переносимости
выполняется.
