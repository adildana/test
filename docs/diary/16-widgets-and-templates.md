# 17. Каталог идей: виджеты и шаблоны

Запрос заказчика: больше идей для виджетов и шаблонов дневника.

Раздел устроен так: сначала — движок виджетов (17.2), без которого каталог превращается в
список несвязанных доработок, затем сам каталог виджетов (17.3) и шаблонов (17.4),
после — четыре идеи, разобранные подробно (17.5), антипаттерны (17.6) и приоритизация с
рекомендуемым первым набором (17.7).

Каталог — это меню, а не план работ. Ни один пункт не обязателен; выбор первого набора
выносится в Q23.

---

## 17.1 Как выбирать из каталога

Четыре критерия, по которым идеи ниже оценены и отсортированы:

1. **Переиспользует существующие движки.** Виджет, который делается из уже готовых частей
   (типы полей шаблонов, вложения, напоминания), стоит в разы дешевле нового.
2. **Не тянет внешние сервисы.** Каждая внешняя зависимость — это согласие пользователя,
   риск отключения сервиса и утечка факта использования (как с музыкой, 16.7).
3. **Полезен без дисциплины.** Трекер, который нужно заполнять каждый день, чтобы он начал
   что-то показывать, будет заброшен. Виджеты, полезные с первого дня, ценнее.
4. **Даёт данные для оглядки назад.** Дневник читают спустя годы: ценнее то, что делает
   старую запись живой (фото, музыка, погода, настроение), чем то, что помогает «управлять
   продуктивностью».

## 17.2 Движок виджетов

Главная мысль раздела: **сначала механизм, потом виджеты**. Двадцать виджетов, сделанных по
отдельности, — это двадцать разных способов хранения данных, двадцать реализаций экспорта и
двадцать источников дефектов доступности. Виджет должен быть типом в реестре, а не отдельной
функцией продукта.

| ID | Приор. | Требование |
| --- | --- | --- |
| WID-01 | M | Виджет — типизированный блок записи: в документе хранится ссылка на экземпляр, данные экземпляра — отдельно (5.7) |
| WID-02 | M | Единый реестр типов: тип, название, иконка, схема данных, версия схемы, представления для экрана и для экспорта. Добавление нового типа не требует изменений в ядре редактора |
| WID-03 | M | Вставка виджета из slash-меню и из группы «Вставка» панели форматирования (ED-07, 2.2) |
| WID-04 | M | Виджет можно свернуть, переместить, продублировать и удалить; удаление обратимо (NAV-41) |
| WID-05 | M | Шаблон может содержать предустановленные виджеты с настройками — например, шаблон «День» с трекером настроения (ED-42, MUS-24) |
| WID-06 | M | У каждого типа есть три представления: интерактивное, печатное (PDF/HTML) и текстовое (Markdown). Виджет без текстового представления не принимается в реестр — иначе ломается экспорт (2.5) |
| WID-07 | M | Виджеты с локальными данными работают офлайн. Виджеты с внешними данными сохраняют **снимок** значения на дату записи и при повторном открытии сети не требуют |
| WID-08 | M | Доступность обязательна для каждого типа: управление с клавиатуры, озвучивание, уважение «уменьшить движение» (NFR-50, NFR-56) |
| WID-09 | M | Виджет, обращающийся к внешнему сервису, требует отдельного согласия; список таких виджетов и их согласий — в настройках приватности (NFR-12, MUS-50) |
| WID-10 | M | Схема данных типа версионируется: записи, созданные предыдущей версией виджета, открываются без искажений (по аналогии с ED-01 / 12.3) |
| WID-11 | S | Те же типы можно размещать на экране «Сегодня» как блоки дашборда (NAV-15) |
| WID-12 | S | «Как в прошлой записи»: перенос состава чек-листа, набора привычек, счётчиков из предыдущей записи одним действием |
| WID-13 | S | Данные виджетов участвуют в поиске и статистике (SRCH-04, STAT-01) |
| WID-14 | C | Конструктор своих виджетов из типов полей шаблона, без программирования (Q27) |
| WID-15 | M | Виджеты не блокируют запись: сбой одного виджета показывает ошибку внутри его рамки, но не мешает читать и редактировать текст |

## 17.5 Четыре идеи, разобранные подробно

Из всего каталога эти четыре дают больше всего при малой стоимости, потому что собираются
из уже спроектированных частей.

### Письмо в будущее

Запись, которую нельзя прочитать до заданной даты. Механика: содержимое скрыто (как
«скрытый блок»), на дату открытия ставится напоминание (PPL-41, механизм из 12.7), в день
открытия приходит уведомление «Письмо, написанное 3 года назад, можно открыть».

Честное ограничение, которое нужно проговорить в интерфейсе: это «замок на честном слове» —
данные лежат у пользователя, и открыть их раньше технически возможно. Обещать
криптографическую невозможность нельзя, пока не решён Q7 про шифрование. Поэтому кнопка
«открыть раньше срока» присутствует, но с предупреждением — так честнее, чем прятать.

Стоимость: 🟡. Нужны: скрытие блока, напоминание, экран открытия.

### История подарков

Проблема, знакомая каждому: не помнишь, что уже дарил, и дарить второй раз одно и то же
неловко. Решение собирается из готового: шаблон «Праздник и подарки» (TPL-06) связывает
человека, дату и позиции вишлиста, а карточка человека получает раздел «Что я дарил» с
годами.

Дальше это работает само: в напоминании о дне рождения (PPL-59) рядом с подсказками
«любит / не любит» появляется строка «в прошлом году вы дарили: набор для рисования» —
и вопрос «что подарить» решается за секунды.

Стоимость: 🟢. Всё уже есть: люди, даты, вишлист, шаблоны. Нужна только связь и один
раздел в карточке.

### Трекер привычек с переносом состава

Отметки по дням, серии подряд, месячная сетка. Ключевая деталь, которая отличает работающий
трекер от заброшенного, — **перенос состава из прошлой записи** (WID-12): пользователь не
пересоздаёт список привычек каждый день, а получает его готовым.

Второе важное решение: пропущенный день не рисуется красным. Дневник — не система контроля;
серии показываются как достижение, а пропуски просто не отмечаются.

Стоимость: 🟡.

### Капсула «этот день»

Блок на экране «Сегодня» и в записи: одна старая запись за эту же дату прошлых лет или
случайная запись старше года. Работает только при накопленных данных, зато с каждым годом
становится ценнее — и именно он превращает дневник из «файла для записей» в вещь, к которой
возвращаются.

Детали, без которых он раздражает: не показывать одну и ту же запись часто (журнал
показов), не показывать записи, помеченные как тяжёлые (флажок «не напоминать»), и
показывать не только текст, но и фото с музыкой того дня (MUS-27).

Стоимость: 🟢.

## 17.6 Антипаттерны

| Антипаттерн | Чем плохо | Что делать |
| --- | --- | --- |
| Двадцать виджетов без движка | Каждый со своим хранением, экспортом и дефектами доступности; поддержка становится дороже разработки | Сначала реестр типов (17.2), потом виджеты по одному |
| Трекеры «для галочки» | Требуют ежедневной дисциплины, а взамен дают график, который никому не нужен | Каждый трекер обязан отвечать: что пользователь узнает через месяц? |
| Красные пропуски и «сгоревшие серии» | Дневник начинает ругать пользователя, и его закрывают | Отмечать достижения, не наказывать за пропуски |
| Внешние интеграции ради галочки | Каждая — согласие, риск отключения и утечка факта использования | Проверить, нельзя ли посчитать локально (17.3, группа Б) |
| Шаблон на 30 полей | Никто не заполняет; шаблон выглядит как анкета в поликлинике | 5–8 полей в основном блоке, остальное — в «Подробнее» (UI-01, UI-02) |
| Автоматические выводы по данным | «Вы грустите по вторникам» — навязчиво и часто неверно | Показывать данные рядом, выводы оставить пользователю |
| Деликатные трекеры без отдельной защиты | Симптомы, лекарства, цикл — данные, утечка которых опаснее всего | Отдельное согласие и блокировка кодом (NFR-04), решение по Q25 |

## 17.7 Приоритизация и первый набор

Рекомендуемый первый набор — то, что даёт максимум ценности при опоре только на уже
спроектированные части (окончательный выбор — Q23):

**Виджеты (5):** настроение дня, чек-лист дня, галерея дня, обратный отсчёт, «этот день в
прошлые годы». Все локальные, без внешних сервисов и разрешений, все — 🟢.

**Шаблоны (8):** День, Итоги недели, Сон, Фильм или сериал, Встреча с человеком,
Благодарность, Идея, Праздник и подарки. Каждый опирается на существующий движок шаблонов и
на связи между модулями (1.4).

**Вторая волна:** трекер привычек с переносом состава, письмо в будущее, погода-снимок,
голосовая заметка, счётчик, прогресс цели; шаблоны итогов месяца и года, тренировки,
путешествия, рецепта.

**Никогда не раньше движка:** любые виджеты групп В и Г — они добавляют внешние зависимости
и разрешения, а значит требуют и согласий (WID-09), и снимков данных (WID-07).
